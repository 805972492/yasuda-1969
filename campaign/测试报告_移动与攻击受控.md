# 测试报告：移动与攻击的「受控性」（2026-11-20 终检）

测试对象：`推演展示_安田讲堂.html`（单文件演示，引擎在页面内）。
测试方法：把 60 条断言注入页面，在无头 Chrome 里跑**真实引擎**（不是另写一套模拟），结果写回 DOM 再解析。
结果：**60 / 60 通过，0 FAIL、0 ERROR**；结构校验 `verify_yasuda_campaign.py` 447 项同时全通过。

复跑方式：

```
python tests_control.py gen                     # 生成 _t.html（内嵌断言）
chrome --headless=new --dump-dom _t.html > _dom.html
python tests_control.py check                   # 打印 PASS/FAIL，失败退出码 1
```

## 一、结论先说

移动与攻击都是**受控**的：位移有步长上限、接触才开火、命令按能力白名单发放、被拒的命令留回执且不消耗资源、逐层只能自下而上、空中平台不能占地。但有 **5 处原本不守恒/不受控的地方**，这轮已修（见第三节）。

## 三、这轮查出并修掉的 5 个问题

| # | 问题 | 症状 | 修法 |
|---|---|---|---|
| 1 | 玩家指挥机動隊时，AI 仍给未下令的警察编组派任务 | 你以为在指挥，别的队自己动了 | `step()` 里 `if(mode==='free' && playerSide!=='机动队') aiPolice()` |
| 2 | 「撤退」命令不清除 | 每回合重复掉 10 士气，退到天荒地老 | `retreat()` 末尾清 `order/target`，回执写「命令结束」 |
| 3 | 「包围」被接受却什么也不做（只扣 3 补给） | 假命令 | 改成真封锁：目标 2 回合内不能修补街垒、守方反击威力减半，并有回执 |
| 4 | 楼层易手后街垒保留负值 | 面板出现「街垒 −37」 | 易手时 `x.b=0` |
| 5 | 机動隊没有「转移」，只能靠攻击命令被动挪动 | 想重新部署就得分兵去打某个点 | 给机動隊加 `move`（直升机、私服仍不给） |

另有 2 个是**测试自身**的问题，顺带修了转换表：单位名里还有 `増援`（日文「増」）、`全斗聯`（「聯」）、`地區`（「區」）没转成简体，导致按名查不到编组。已补进 `localize_simplified.py` 并重新生成，现在全站无日文假名（除 `sources.json` 的出处原题）。

## 四、属于设计选择、不算缺陷的部分

- **攻击命令跨回合保持**，直到目标被拿下或自己放弃；不需要每回合重下。
- **接触才开火**：`reach = contact_km + 0.10~0.13 km`，在距离外只机动，不结算伤害。
- **直升机只能压制**：街垒压到 8、不占地、不占层；要继续打只能靠地面部队。
- **民青是第三方**：玩家不可指挥；警方 AI 不把民青据点列为目标（史实中警方保护民青据守的医学部本館）。
- **数字不反推**：清层才计被捕，无人馆的「解除封锁」不计；史料异文并列不取平均。

## 五、没测到的部分（诚实交代）

- **UI 点击链路**没有做自动化点击（按钮、下拉、地图拖拽），只有引擎层断言 + 截图目视；按钮与命令是同一套 `caps()`，风险较低但不是零。
- **地图瓦片依赖网络**（地理院），离线只剩矢量轮廓与圆点。
- **30 分钟一步的粒度**决定了「同一回合内的先后」不可分辨；测试只覆盖回合边界上的状态。
